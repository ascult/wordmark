## Question

语境义的置信度怎么呈现，「拿不准」时怎么办？

三种来源天然对应三档置信度（术语已入 `CONTEXT.md`）：**方法定位到**（与译文严格一致，最高）>
**模型选中** > **回退首义项**（最低）。要定：

- 这三档在 UI 上区分吗？区分的话怎么标（配色 / 下划线 / 悬停提示），要不要可关。
- 悬停是否给出**整句译文**让人自己判断（原型第 5 条建议）。
- 最低档（回退首义项）到底标不标——标了可能误导，不标则覆盖率下降。
- 与现有设计取舍的冲突：现在「点击中文部分 = 我已认识该词」，标注是 12px、`user-select:none`、
  只着色。加置信度会不会破坏「不打断阅读流」。
- 可用一个便宜的原型（静态 HTML 或改 `prototype/`）对照两三种样式再决定。

## 补注（发现并行实现后）

这套「三档来源」的框架要改：现行实现里**没有「方法定位」这一档**，只有两种结果——
打分器选中（`SensePick.sense`）与拿不到就保持词典义。所以真正要定的是：
「打分器选中」要不要在 UI 上和原词典义区分、怎么区分。
`SensePick` 里带了 `scores`（各义项分数）与 `count`，接口注释说它是「便于调试与『模型是否犹豫』的判断」——
也就是说「模型犹豫时降级」这件事在数据上是可行的，待决。

## Answer

用户委托我决策。先确认实现现状：`GlossRenderer.updateGlossText(id, gloss)` 已经能做**按处替换**，
pipeline 也是「先标词典义 → 拿到结果原地换掉」，所以交互时序**已经落地**，本票只需定「显示」。

**1) 正文里不做任何视觉区分（决定：不区分）。** 语境义替换后，外观与词典义完全一致——
不加勾、不加符号、不换配色、不加悬停。
理由三条：现有设计取舍是「只着色、12px、`user-select:none`、不打断阅读流」，加第二套视觉语言会把注意力
从正文拉回标注本身；用户对这个区别**无法采取任何行动**；逐处标记会让同页出现两种标注，破坏一致性。

**2) 但「有没有生效」必须可见——移到弹窗（聚合）与设置页（细节）。**
静默回退是设计选择，代价是用户无法判断功能是否在工作。所以新增 `PageStats` 字段：
`contextual`（本页用上语境义的处数）与 `senseReachable`（服务是否可达），弹窗显示。
候选义项与 `scores` 只在设置页/调试可见。

**3) 悬停给整句译文：不适用，不做。** 那条建议属于原型的「方法」路线（需要译文），
现行实现根本不取译文（见作废的 03）。

**4) 拿不到语境义时照常标词典义，不因此少标。** 标注由词表难度门槛决定，与语境义是两件事；
服务不可达时表现与现状完全一致。

**5) 不做基于 `scores` 的阈值降级。** 没有校准过的阈值就是猜，猜错还看不见；
分数只用于调试与评测。等 06 的人工集能校准置信度之后再谈。

**6) 点击「已认识」仍是词级语义**：同一词在页内两处不同义项时，点任一处都会把该词元整体标为已知、
两处一并移除（`wordmark:mark-known` 本就是词级）。保持既有语义，spec 里写明，免得日后被当 bug 修。

**7) 实现约束（spec 明文）**：`updateGlossText` 必须精确到那一处，不能按词元批量替换；
替换仍走 `textContent`，不得改变标注的文本结构，否则会破坏 `unmarkAll` 的精确还原。
