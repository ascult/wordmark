## Question

把 teacher 蒸馏出的「义项按真实用法频次排序」（`distilled-senses.json`）并进生产数据吗？

背景：原型用 9B teacher 跑了 1,500 条「词 × 句」观察、覆盖 488 词，留一验证显示
「按真实用法排序取第一」比「永远取上游词典第一义项」高 15.6pp（70% vs 55%）。
但它的上限受 teacher 自身忠实度限制（teacher 与方法一致率仅 71%），且当前只覆盖 488 词。

要定：

- **是否随扩展打包**：它零运行时成本、无网可用，正好补上「默认开但只有本地网络」时的离线默认顺序。
- **与 02 定下的 `senses[0] === gloss` 冲突怎么解**：有先验时是否允许重排首候选？
  （人工整理的 `gloss` 作首候选是 02 的硬约束，两者需要调和。）
- **覆盖率**：488 / 3,039 太低——要不要扩大蒸馏（重跑 teacher，需要 laptop + ssh 那套），
  扩到多少、用哪个语料。
- **置信度语义**：按先验选的义项算哪一档（`CONTEXT.md` 里现在只有方法定位 / 模型选中 / 回退首义项三档）。

闭票时给出：先验的字段形状与打包决定 + 它与 `senses[0]` 的优先级 + 覆盖目标。

## Answer

用户委托我决策。

**结论：本次 spec 不打包义项先验。**

本轮实测的事实：
- `distilled-senses.json` 覆盖 **488 词**；多义项词共 2,413、全体词条 3,039 → 覆盖率 **20.2% / 16.1%**。
- 488 词里 **109 词（22.3%）的 `top != 0`**，即先验会改变「首项」——这正是 +15.6pp 的来源。
  （先前误判为「先验等于首项」：`senses` 数组并未重排，排序信息在 `top` 下标里。）
- 标签来自 teacher，交叉校验下 teacher 与方法一致率仅 71%，所以它是**频率先验**，不是正确性。

理由：先验唯一能起作用的位置是「无 endpoint 时的默认顺序」，而本次回退已定为现状
（`senses[0]`，即人工整理的 `gloss`）。为 16% 的词加一整套数据字段 + 构建 + 校验，收益不抵成本。

**若将来打包，规则先定死**（写进 spec 的「已知缺口」）：
1. 先验**只能重排 `senses[1..]`**，永不覆盖 `senses[0] === gloss`（02 的硬约束）；
2. 先验选出的义项**不是语境义**——它没看句子，只能算最低档（回退 / 先验），不得对外宣称
   「这句里的意思」。这保护 `CONTEXT.md` 的定义：语境义必须由句子决定；
3. 把覆盖从 488 扩到 2,413+ 依赖 laptop + teacher 那套开发期工具，属另一个 effort。

本票因此按「超出本次目的地」关闭，记入 map 的 Out of scope。
