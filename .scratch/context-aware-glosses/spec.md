# Spec：语境义标注（标注的是这个词在这一句里的义项）

> 本 spec 由一次 wayfinder 作图会话（`.scratch/context-aware-glosses/map.md`）综合而成，
> 十张决定票均已关闭，另有一条 ADR：`docs/adr/0001-local-only-sentence-context.md`。

## Problem Statement

读英文文章时，wordmark 给出的中文释义是**词典里那个词的默认义项**，不一定是这一句里用的那个。

比如 `engine` 在「…both the engine and the rudder of great work.」里是隐喻义的「驱动力/推动力」，
但标注出来的是首义项「发动机/引擎」。**一个错的释义比没有释义更糟**：它误导理解、消耗信任，
而读者往往不会察觉自己读到的是另一个义项。读者因此必须在「相信标注」和「再去查一次」之间二选一，
而不查正是这个工具存在的理由。

## Solution

扩展可以把**这个词所在的那一句**发给一个**由用户自己在本机（或局域网）运行的打分服务**，
拿回「该词的几个候选义项里，哪一个最合这一句」，然后把那一处释义**原地换掉**。

- 只发**含生词的那一句**与该词，不发页面正文、URL、浏览记录。
- 只接受**本机与局域网**地址，绝不发往公网。
- **默认关闭**，由用户显式开启。
- 服务没起、超时、词不在义项表里——都只是「这次没拿到」：页面照常显示词典义，**不报错、不打断阅读**。

## User Stories

1. 作为一个英语读者，我希望标注出的是这个词在**这一句**里的意思，这样我不用为了确认一个词再跳出去查。
2. 作为一个英语读者，我希望同一个词在同一页面里的两处**各自**标注（可能不同义项），因为一处对不代表另一处对。
3. 作为一个英语读者，我希望换掉释义这件事**不要在视觉上大惊小怪**（不加符号、不换颜色），因为它不该抢正文的注意力。
4. 作为一个英语读者，我希望语境义与词典义在外观上**完全一致**，这样页面里的标注是同一种语言而不是两种。
5. 作为一个英语读者，我希望页面**先正常标注出来**，语境义到手后再原地替换，这样我不会为了等一个模型而看到空白页面。
6. 作为一个英语读者，我希望服务没起的时候页面**和以前一模一样**，不要弹错误、不要留空、不要少标。
7. 作为一个英语读者，我希望**点击中文释义仍然等于「我认识这个词」**，并且仍然按**词元**生效（同一词的多处一并移除）。
8. 作为一个英语读者，我希望同一个词、同一句话，重复出现时**不要重复请求**。
9. 作为一个英语读者，我希望长页面不要因为逐句挑选而变慢或卡住——宁可少挑几处，也不要拖慢阅读。
10. 作为一个英语读者，我希望挑选**按阅读顺序**进行，这样正文靠前的部分优先被照顾。
11. 作为一个隐私敏感的读者，我希望这个功能**默认关闭**，由我自己打开。
12. 作为一个隐私敏感的读者，我希望知道**到底发出去了什么**：只是含生词的句子和那个词。
13. 作为一个隐私敏感的读者，我希望扩展**拒绝把整句发往公网地址**，哪怕我手滑填了一个公网域名。
14. 作为一个隐私敏感的读者，我希望即使我**导入了一份别人给的配置 JSON**，也绕不开上面那条限制。
15. 作为一个隐私敏感的读者，我希望 README 的隐私承诺是**准确的**，而不是一句听起来好听的话。
16. 作为一个自托管的用户，我希望有一个**清楚的启动方式**：装什么依赖、怎么下模型、怎么起服务、怎么自检。
17. 作为一个自托管的用户，我希望扩展能告诉我**服务到底通没通**，而不是让我猜为什么释义没被换掉。
18. 作为一个自托管的用户，我希望扩展与服务之间的**协议有版本号**，版本对不上时安静地回退，而不是给出奇怪的结果。
19. 作为一个自托管的用户，我希望**服务端点可配**（含端口），因为我的服务不一定跑在默认端口。
20. 作为一个自托管的用户，我希望跨机器时能把远端服务用隧道映射到本机，从而**不必放开局域网白名单**。
21. 作为一个自托管的用户，我希望授权是**按 origin 申请**的，而不是装扩展时一次性全量授权。
22. 作为一个排障的人，我希望设置页能看到**候选义项与分数**，这样我能判断模型是在认真挑还是在乱猜。
23. 作为一个排障的人，我希望弹窗能看到**本页有多少处用上了语境义**、以及**服务是否可达**。
24. 作为一个维护者，我希望多义项数据**能从仓库复现**，而不是依赖一个被 gitignore 的克隆。
25. 作为一个维护者，我希望多义项数据**不与词表分片混在一起**，否则合并脚本会把它当词条校验并让构建失败。
26. 作为一个维护者，我希望**只有一个**版本化的打分器适配器，这样「71.8%」对应一个确定的产物。
27. 作为一个维护者，我希望大二进制（几百 MB 的权重、特征缓存）被 `.gitignore` 挡在仓库外。
28. 作为一个维护者，我希望**评测与生产共用同一套切句**，否则测出来的数不是线上的数。
29. 作为一个维护者，我希望有一个**人工标注的义项级小集**，能回答「比现在的首义项到底好多少」。
30. 作为一个维护者，我希望上线门槛是**统计上站得住**的（提升的置信区间不含 0），而不是看一个同分布留出集的漂亮数字。
31. 作为一个维护者，我希望评测台能**离线复现**：网络与模型调用落盘缓存、默认重放，这样 CI 里也能跑。
32. 作为一个维护者，我希望**一次请求失败不被记成「这个词没得选」**，否则一次超时会永久禁掉一整批。
33. 作为一个维护者，我希望**设置项的默认值是自洽的**：单批工作量和超时阈值要对得上，不能在长页面上必然超时。
34. 作为一个维护者，我希望有一个 ADR 记录「为什么一个以隐私为卖点的扩展会向外发句子」，免得日后被当成 bug 改掉。
35. 作为一个维护者，我希望被否决的路线（页内推理、公网服务、让模型直出释义）**有据可查**，不必重新论证一遍。

## Implementation Decisions

### 数据

- 多义项表**作为源数据入库**，放在**独立的目录** `data/senses/`（当前一份：`cet4.json`，2,602 词 /
  11,421 条义项）。**绝不能**放进现有词表分片目录：合并脚本会把那些目录下的每个 JSON 当词条数组校验，
  而多义项表没有 `pos/gloss/level`，会让构建直接失败。
- 形状：`{ "<word>": ["义项", …] }`；每词 ≤6 条。单条义项的长度上限是 **32 字**——这是生成器的结构上限
  （最多 3 个「原子」用 `/` 连接、单原子 ≤10 字），**不是**词表里那条 14 字的展示释义规则，两者不可混用。
- 生成器提升为正式的导入脚本（`scripts/import-senses.mjs`，`npm run import:senses`），与既有词表导入脚本对称；
  它需要外部 TypeWords 克隆，但**产物入库后 `git clone` 即可重建整条链路**，生成器只用于追溯与更新。
  入库的产物必须与打分器实际在用的那一份**字节一致**——换掉它，就等于换掉了「71.8%」所对应的产物。
- **构建时校验**（挂在 `npm run dict` 上，fail-fast）：词元是小写 ASCII 且在词表里（凭空造词即失败）、
  义项非空、含中文、不超结构上限、不重复。
- 义项表**不进扩展包**：由打分服务持有，扩展只发「句子 + 单词」。这既省体积（义项表 229K vs 现有词典 192K），
  也让义项表可以不发版迭代。
- **已知缺口**：437 条没有多义项的词（人工整理与基础档，恰是最该判义项的难词）本次不补。

### 打分器与协议

- 打分器是**判别式打分**：编码器 + 线性头，同一题的 K 个义项一起组内 softmax，取 argmax。
  结构上不会输出非法序号；义项数可变；义项表放服务端。
- **必须逐题前向，不能跨题合批**。训练时按「本题最长」右填充、取**最后一个位置**的隐状态——
  这是个被训练固定下来的池化约定。把不同题目混进同一矩形批次会让读出位置平移，与训练分布不一致。
  （要真正的批次吞吐得先重训成定宽填充；本次不做，见 Out of Scope。）
- 协议固化：
  - `POST /select`：入参 `{ items: [{ id, sentence, word, senses? }] }`；
    出参 `{ results: [{ id, index, selected, senses, scores, ms }] }`。`senses` 省略时由服务端查表（推荐）。
  - `GET /health`：返回模型、适配器、义项表来源、多义词数量、单请求上限。
  - `index: -1` + `reason`（`unlisted` / `single-sense`）表示「没得选」，**这是常态而非错误**，调用方保持原释义。
  - 超过单请求上限即拒。
  - **新增 `protocolVersion`**，扩展核对不上即静默回退。

### 页内链路

- 只对**含生词的**句子取上下文，且按当前生词线的候选词筛。
- 上下文取该文本节点最近的**块级祖先**的文本，**排除扩展自己插入的释义**（中文混进英文上下文会拉低质量），
  按句末标点切句并**保留字符偏移**，过长时**以目标词为中心**裁到上限（避免把一个词切两半）。
- 缓存键为「词 + 句子」（含否定结果），页内 LRU；页内挑选处数有上限。
- **先标词典义，拿到结果后按处替换。** 替换必须精确到**那一处**，不能按词元批量替换
  （同一词在一页里可能两处、两个义项）；替换必须仍走纯文本写入，不得改变标注的文本结构，
  否则会破坏「精确还原原文」的既有保证。
- **绝不抛错**：服务没起、超时、返回垃圾——都只是「这次没拿到」，页面继续用词典义。

### 批处理与预算

- **分片顺序发**：不把整个页上限一次发出去，切成小批（默认 32 题/批）顺序发送，每批独立超时、独立缓存。
  服务端有全局锁（图执行非线程安全），**并发无意义**。
- 单批超时默认 **3000ms**（32 题约 2 秒，留 50% 余量）。设置页仍允许 500–60000ms。
- **失败不落缓存**：只有服务端明确给出 `index: -1` 才写否定结果。超时 / 连不上 / 非 2xx / 响应格式不对
  **一律不缓存**，留给滚动与重扫时重试。**（这是必须修的现存缺陷：现在失败与「没得选」被缓存成同一件事，
  一次超时会把整批永久禁用。）**
- 不做自动重试；不引入「可见区优先」，候选按阅读（DOM）顺序先到先得。

### 设置（schema 变更）

新增一个语境义设置组，字段与默认值：

- `enabled`：默认 **false**。
- `endpoint`：默认指向本机回环地址与默认端口。
- `timeoutMs`：默认 3000，范围 500–60000。
- `maxPerPage`：默认 300，范围 0–5000；语义是「本页最多挑多少处」。

### 权限与校验

- 端点**只允许本机与局域网**：回环（`localhost` / `127.0.0.0/8` / `::1`）、私网字面量
  （`10/8`、`172.16/12`、`192.168/16`、`169.254/16`）、IPv6 ULA `fc00::/7`，以及 `.local` / `.home.arpa`
  结尾的主机名。公网域名与公网 IP 一律拒绝；http 与 https 同等对待。
- **校验必须落在设置收敛层**（导入的 JSON 也走那里），设置页复用同一判定函数，消灭两套规则。
  **（现存缺陷：设置收敛层不限 host，导入一份 JSON 就能把整句发到公网 https 地址。）**
- 运行时按 origin 申请 host 权限；未授权即不工作，且不报错。

### 默认姿态与对外说法

- **默认关闭**（这条推翻了作图过程中一度拍下的「默认开」）。开启后，含生词的整句会发往 endpoint，
  属隐私敏感行为，必须由用户显式打开。
- README 的「默认纯离线、不发任何网络请求」收窄为：默认离线；语境义挑选需显式开启，且只走本机/局域网。
- 该转向由 `docs/adr/0001-local-only-sentence-context.md` 记录（含被否决的替代方案与后果）。
- 设置页文案要说清三件事：发什么（含生词的整句 + 该词）、发到哪（本机/局域网，绝不公网）、
  拿不到会怎样（照常显示词典义、不报错）。

### UI

- **正文里不做任何视觉区分**：不加勾、不加符号、不换配色、不加悬停。理由是既有取舍为「只着色、不打断阅读流」，
  且用户对这个区别无法采取任何行动。
- 「有没有生效」改由**弹窗聚合**显示：本页用上语境义的处数 + 服务是否可达（需扩展页面统计的字段）。
  这是「静默回退」的必要补偿——否则服务一直悄悄回退，用户无从察觉。
- 候选义项与分数只在**设置页/调试**可见。
- 不做悬停整句译文（现行机制根本不存在译文）。
- 不做基于分数的阈值降级：没有校准过的阈值就是猜，且错得看不见。

### 交付形态

- 打分服务定义为**自托管的伴随服务**，从原型目录**搬出去**（原型目录的自我定位是「不是生产实现」，
  而扩展已经把它当正式依赖）。
- **只支持 Apple Silicon**；其它平台明确不承诺。
- 基座模型**不入仓库**（文档给模型 ID 与下载命令）；适配器**入仓库但版本化且只留一个**
  （现存两个适配器并存，「71.8%」对应不上确定产物）；义项表入库。
- `.gitignore` 必须排除大二进制（数百 MB 的权重、特征缓存、`__pycache__`）。

### 评测

- **绝对质量用人工义项级小集**（150–200 条，盲标，抽样按真实义项数分布分层——真实文章平均 4.67 个义项，
  高于留出集的 3.59）；格式含 `senses`（生产形状）与 `gold` 下标，另有 `"none"` 表示这句没有合适义项。
- **相对排序用既有 teacher 标签数据集**：只回答「A 比 B 好」，**不得写成准确率**；必须随报告披露两条噪声
  （标签来自 teacher，一致率仅 71%；句子边界质量差）。
- 主指标是人工集 top1；辅以 top2、覆盖率、回退率、请求次数、延迟分位、缓存命中。
  「与译文相容率」只作置信度信号，不作准确率。
- 基线：永远首义项（现状）、打分器选中。（原设计里与方法相关的基线随机制作废而取消。）
- 新评测台沿用既有基准的表格与「存档 / 对比」约定；**网络与模型调用落盘缓存、默认重放**，无网可复现。
- **上线门槛**：人工集 top1 相对「永远首义项」的提升，其 95% 置信区间（配对 bootstrap）**不含 0**。
  留出集上的 71.8% 只作相对指标。
- **硬约束：评测与生产共用同一套切句。** 切句放在 Node 侧复用生产逻辑，中间用 JSON 交给打分器，
  不许在打分服务里重写一遍，否则评测与线上会悄悄分叉。

## Testing Decisions

- **缝只有一个：`SensePicker`**（页面流水线已有的注入点）。测试注入一个假 picker，断言**外部行为**：
  释义先按词典义出现、拿到结果后**只有那一处**被替换、同一词的另外一处不受影响、拿不到结果时保持原样、
  页上限生效、重扫后结果稳定不衰减。不测内部实现细节。
- `SenseSelector` 的分片、缓存语义（**失败不落缓存**、`index:-1` 落否定缓存、预算上限）
  在它**自身已有的请求函数注入口**上单测——这是同一个缝的实现级测试点，不是新缝。
- 沿用既有页面级测试的写法与用例风格（阈值、已知词、幂等性、页上限、XSS 回归、重扫不衰减）。
- 不做端到端的真服务测试进 spec 的必跑集：真浏览器链路依赖本机跑得起 mlx 服务，不作为门禁。

## Out of Scope

- **把打分器搬进浏览器**（ONNX/WebGPU 页内推理）。注入点保留，但不作为本次交付路径；
  若将来要走，多义项表「不进扩展包」的决定需要重新评估。
- **非 Apple Silicon 平台**（Windows / Linux / Intel Mac）：不做，也不承诺。
- **把整句译文发往公网服务**（MyMemory 等）：与隐私姿态冲突，且匿名配额极低、数据长期留存并共享第三方。
  现有针对**单词**的在线兜底保持不变、不动。
- **义项先验**（按真实用法频次排序）的打包与扩大蒸馏：它只影响离线默认顺序、不参与语境义判定，
  且当前只覆盖 488 / 3,039 词。
- **为重训「定宽填充」而改批次策略**：分片已让超时可控，重训只提升吞吐，当前场景不值得。
- **给那 437 条无多义项的词补义项**：依赖已选定的链路，留作后续。
- Firefox / Safari 适配；生词本导出到 Anki / CSV（既有 roadmap 项，与本目的地无关）。

## Further Notes

**作图期间发现、需要在实现时一并处理的现存缺陷**（两条待修，一条已修）：

1. **已修**：在线查词的页内代理把「消息信封」当成已解包数据取字段，导致**在线查词恒返回 null**，
   这条路径此前完全失效（只是被类型检查先拦下）。修好后开启在线兜底才会真正发请求。

**工程前置**（不属于本 spec 的功能范围，但会挡住验证）：

- 仓库目前几乎全是未纳管文件（`git ls-files` 只有 `LICENSE` 与 `README.md`），没有回滚点。
  做首次基线提交前**必须先扩 `.gitignore`**，否则数百 MB 的权重与特征缓存会进仓库。
- 本机 Node 由 `fnm` 管理且不在登录 shell 的 PATH 里，跑 `npm run …` 要先把对应 bin 目录加进 PATH。
- README 严重滞后：完全没提语境义这个功能，测试数写着 153（实际 **223**），架构图缺了本轮新增的模块。
