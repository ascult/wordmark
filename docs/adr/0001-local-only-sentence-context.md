# ADR 0001：语境义挑选只把「含生词的句子」发往本机或局域网端点

- 状态：已采纳
- 日期：2026-09-14
- 相关：`.scratch/context-aware-glosses/issues/04-privacy-permissions-ux.md`、`10-scorer-delivery.md`

## 背景

语境义（这个词在这一句里对应哪个义项）无法只靠词表离线判定：词表里每条记录只有一个默认义项，
是词典编者的顺序，不是这一句里的那个。真正判它需要**句子**这个上下文。

README 目前对外的承诺是「默认**纯离线**：3,039 条内置词表，不发任何网络请求」。

## 决定

1. 语境义挑选**默认关闭**，必须由用户显式开启。
2. 开启后，只把**含生词的那一句**（连同该词）发往用户自己配置的端点；**不发**页面正文、URL、浏览记录。
3. 端点**只允许本机或局域网**：回环（`localhost` / `127.0.0.0/8` / `::1`）、私网字面量
   （`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、IPv6 ULA `fc00::/7`）、以及 `.local` / `.home.arpa`。
   公网域名与公网 IP 一律拒绝，http 与 https 同等对待。
4. 服务不可达 / 超时 / 没有可用义项 → **静默保持词典义**，不报错、不打断阅读。

## 被否决的替代方案

- **把模型打进扩展、页内推理**（ONNX/WebGPU）：不引入网络，但体积、平台与工程量都大。
  未否决其可能性——`SensePicker` 接口即为它留了扩展点；但它不是本次的交付路径。
- **发往公网翻译/LLM 服务**：与隐私承诺直接冲突；且实测 MyMemory 匿名配额仅 5,000 字符/天、
  明令禁止一次超过一段、提交内容长期留存并共享给第三方。
- **让模型直接生成释义**：原型实测其释义有相当比例在译文里找不到对应，不可控也不可解释；
  改为「在已有义项里挑一个」，输出永远是真实词典义。

## 后果

- README 的「默认纯离线」必须收窄为「默认离线；语境义挑选需显式开启，且只走本机/局域网」。
  这不是措辞微调，而是产品承诺的边界移动，所以要留下这条 ADR。
- 新增一条 host 权限申请流程，以及「端点不可达」这个新的失败模式（表现为无变化，而非报错）。
- 用户需要自己运行一个打分服务。当前它是原型脚本（`prototype/mt-align/xenc/serve.py`），
  交付形态另议（票 10）。
- 校验必须落在**设置收敛层**（`sanitizeEndpoint`），不能只落在设置页 UI——否则导入一份 JSON 配置
  就能把整句发到公网地址。
- 推荐做法：跨机时用 `ssh -L` 隧道把远端服务映射到 `127.0.0.1`，这样连局域网白名单都不需要开。
